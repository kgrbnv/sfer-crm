## 1. Контекст и проблема

### 1.1 О бизнесе

**sfer.ai** — бутик AI Native решений для бизнеса:
- Обучение команд AI-практикам
- Дипдайвы по направлениям (HR, Маркетинг, Топ-менеджмент)
- Внедрение AI-автоматизаций

**Ключевые метрики:**
| Показатель | Значение |
|------------|----------|
| Средний чек | 978K руб |
| Медиана чека | 750K руб |
| Маржинальность | 60%+ |
| WinRate | 14% |
| Контактов за год | 160 |
| Цель роста | 4x (100M руб) |

### 1.2 Текущее решение (Notion)

**EDU Deals Database** — база сделок в Notion.

**Текущие поля:**
- Status (воронка): Cold Outreach Backlog → Lead → Qualified → Proposal → Negotiation → Pending → Closed
- Priority: Low / Medium / High
- Estimated Value (руб)
- Probability (%)
- Projected Revenue (формула)
- Person, Tg username
- Leader (ответственный)
- Причина отказа
- Связи: Customer, Company, Projects, Payments, Offers

### 1.3 Проблемы текущего решения

**Из разговора с Олегом (B2B консультант):**

> "Notion CRM не даёт какой-то прозрачной аналитики исторической. Сколько у меня менеджер провёл сделок — мне вообще не даёт."

> "Если в Notion нельзя настроить обязательные поля — всё как бы. Он забыл, не отфильтровал, ты потерял эту сделку, статистики не увидел."

**Конкретные проблемы:**
1. **Нет трекинга касаний** — не фиксируются звонки, сообщения, количество контактов
2. **Нет истории переписки** — переписка в Telegram/WhatsApp не привязана к сделке
3. **Нет обязательных полей** — менеджер забывает заполнять статусы и даты
4. **Нет аналитики** — невозможно выгрузить конверсии по этапам, WinRate по стейкхолдерам
5. **Нет автоматизации** — нет автоматических follow-up, напоминаний
6. **Нет контроля менеджеров** — не видно активность (сколько касаний в день)
7. **Нет ICP-полей** — отрасль, оборот, количество сотрудников, сегмент

### 1.4 Текущий workflow (сохранить!)

**AI-создание карточек из транскрипций** — киллер-фича:
> "Я пишу: создай по транскрипции встречи сделку. И он сам создаёт профиль компании, профиль клиента, профиль сделки и бриф по ней."

Это ОБЯЗАТЕЛЬНО сохранить и развить.

## 2. Цели проекта

### 2.1 Бизнес-цели

1. **Увеличить количество контактов** — с 160/год до 160/месяц
2. **Повысить WinRate** — с 14% до 20%+ за счёт системной работы
3. **Обеспечить прозрачность** — видеть активность и результаты в реальном времени
4. **Автоматизировать рутину** — follow-up, напоминания, отчёты

### 2.2 Технические цели

1. **Простота внедрения** — старт за несколько часов, не месяцы
2. **AI-first** — интеграция с Claude/GPT для автозаполнения
3. **Интеграция с мессенджерами** — Telegram, WhatsApp в одном месте
4. **Гибкость** — легко адаптировать под изменение процессов

### 2.3 Почему не AmoCRM/Bitrix24

> "меня убедили, что быстрее и проще навайбкодить себе CRM на базе AirTable — типа гораздо меньше головной боли, чем интегрировать Амо"

**Аргументы:**
- Интеграция AmoCRM требует времени и денег на интегратора
- Избыточный функционал для команды 2-3 человека
- Нет нативной интеграции с нашим AI-workflow
- Месячные платежи vs. разовая разработка

## 3. Функциональные требования

### 3.1 Воронка продаж

**Этапы воронки:**

```
[База] → [Outreach] → [Диалог] → [SQL] → [Встреча] → [КП] → [Переговоры] → [Оплата/Lost]
```

| Этап | Описание | Автопереход |
|------|----------|-------------|
| **Cold База** | Выгружено из контркомпаса | — |
| **Outreach** | Сообщение отправлено | При отправке сообщения |
| **Диалог** | Клиент ответил | При получении ответа |
| **SQL** | Квалифицированный лид (интерес подтверждён) | Ручной |
| **Встреча назначена** | Согласовано время | При создании события в календаре |
| **Встреча проведена** | Состоялась | Автоматически после времени встречи |
| **КП отправлено** | Коммерческое предложение | При отправке документа |
| **Переговоры** | Обсуждение условий | Ручной |
| **Оплата** | Сделка закрыта | При получении оплаты |
| **Lost** | Отказ | Ручной + причина |

### 3.2 Карточка сделки

**Обязательные поля:**
| Поле | Тип | Описание |
|------|-----|----------|
| Название | text | Краткое название сделки |

| Контакт | relation | Ссылка на карточку контакта |

**ICP-поля (для аналитики):**

| Отрасль | select | IT, Fintech, FMCG, Девелопмент, Pharma, etc. |

| Оборот компании | select | <100M / 100M-500M / 500M-1B / >1B |
| Количество сотрудников | select | <50 / 50-200 / 200-1000 / >1000 |
| Стейкхолдер | select | CEO / CTO / HRD / CMO / Other |

**Дополнительные поля:**

### 3.5 Трекинг касаний

**Виды касаний:**
- Сообщение отправлено (Telegram/WhatsApp/Email)
- Сообщение получено
- Звонок исходящий
- Звонок входящий
- Встреча (онлайн/офлайн)
- Документ отправлен

**Для каждого касания:**
| Поле | Тип |
|------|-----|
| Тип | select |
| Канал | select |
| Дата/время | datetime |
| Контент | text |
| Результат | text |
| Сделка | relation |
| Контакт | relation |

### 3.6 Автоматизация

**Триггерные действия:**

| Триггер | Действие |
|---------|----------|
| Нет ответа 24ч | Автоматический follow-up (черновик) |
| Нет ответа 72ч | Уведомление менеджеру |
| Встреча через 24ч | Напоминание в Telegram |
| Сделка без активности 7 дней | Уведомление руководителю |
| Новый лид | Автоприсвоение менеджеру |

**AI-автоматизация:**
- Создание карточки сделки из транскрипции встречи
- Генерация Summary по истории переписки
- Подсказки по next steps
- Автозаполнение ICP-полей по названию компании

### 3.7 Аналитика и отчёты

**Дашборд:**
- Воронка (визуализация этапов с суммами)
- WinRate по периодам
- Конверсия по этапам воронки
- Средний цикл сделки
- Projected Revenue (сумма × вероятность)

**Срезы аналитики:**
- По менеджеру
- По отрасли
- По сегменту
- По стейкхолдеру
- По источнику лида

**Активность менеджеров:**
- Количество касаний за день/неделю
- Количество встреч
- Количество отправленных КП
- Время реакции на входящие

## 4. Нефункциональные требования

### 4.1 Производительность
- Загрузка списка сделок < 1 сек
- Поиск по базе < 500 мс

### 4.2 Доступность
- Web-интерфейс (адаптив для мобильных)
- Telegram-бот для быстрых действий

### 4.3 Безопасность
- Аутентификация через Google OAuth
- Разграничение прав (админ/менеджер/viewer)

### 4.4 Масштабируемость
- Текущая нагрузка: 2-3 пользователя, 200 сделок/год
- Целевая: 5-10 пользователей, 1000 сделок/год

## 7. Технический стек

### 7.1 Варианты реализации

**Вариант A: AirTable + Автоматизация**
- База: AirTable
- Автоматизация: Make/Zapier
- UI: AirTable Interface + Extensions
- Плюсы: быстрый старт, гибкость
- Минусы: лимиты AirTable, стоимость автоматизаций

**Вариант B: Supabase + Custom UI**
- База: Supabase (PostgreSQL)
- UI: Next.js + Tailwind
- Автоматизация: Supabase Edge Functions
- Плюсы: полный контроль, масштабируемость
- Минусы: больше разработки

**Вариант C: Notion + n8n**
- База: Notion (текущая)
- Автоматизация: n8n
- Плюсы: минимальные изменения
- Минусы: ограничения Notion остаются

### 7.2 Рекомендация

**Вариант B (Supabase + Custom UI)** — наиболее подходящий:
- Уже есть Supabase проект для метапроекта
- Полный контроль над структурой данных
- Можно интегрировать с существующим RAG-хранилищем
- Возможность масштабирования

## Приложение A: Схема базы данных (Supabase)

```sql
-- Схема: crm

CREATE SCHEMA IF NOT EXISTS crm;

-- Компании
CREATE TABLE crm.companies (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    inn TEXT,
    industry TEXT,
    segment TEXT,
    revenue_range TEXT,
    employees_range TEXT,
    website TEXT,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- Контакты
CREATE TABLE crm.contacts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    company_id UUID REFERENCES crm.companies(id),
    name TEXT NOT NULL,
    position TEXT,
    phone TEXT,
    email TEXT,
    telegram TEXT,
    whatsapp TEXT,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- Сделки
CREATE TABLE crm.deals (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    company_id UUID REFERENCES crm.companies(id),
    contact_id UUID REFERENCES crm.contacts(id),
    status TEXT NOT NULL DEFAULT 'cold_base',
    estimated_value NUMERIC,
    probability INTEGER,
    leader_id TEXT,
    source TEXT,
    ping_date DATE,
    deadline DATE,
    lost_reason TEXT,
    summary TEXT,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now(),
    last_activity_at TIMESTAMPTZ DEFAULT now()
);

-- Касания
CREATE TABLE crm.activities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    deal_id UUID REFERENCES crm.deals(id),
    contact_id UUID REFERENCES crm.contacts(id),
    type TEXT NOT NULL, -- message_out, message_in, call_out, call_in, meeting, document
    channel TEXT, -- telegram, whatsapp, email, phone, zoom
    content TEXT,
    result TEXT,
    created_at TIMESTAMPTZ DEFAULT now()
);

-- Индексы
CREATE INDEX idx_deals_status ON crm.deals(status);
CREATE INDEX idx_deals_company ON crm.deals(company_id);
CREATE INDEX idx_activities_deal ON crm.activities(deal_id);
CREATE INDEX idx_activities_created ON crm.activities(created_at);
```
